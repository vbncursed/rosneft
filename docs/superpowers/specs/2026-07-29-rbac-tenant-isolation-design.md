# Разграничение прав: изоляция тенантов и сессия в куке — дизайн

Дата: 2026-07-29
Статус: утверждён, готов к планированию реализации
Смежная спека: [`2026-07-29-audit-hardening-design.md`](2026-07-29-audit-hardening-design.md)

## Задача

Аудит функциональности от 2026-07-29 оценил разграничение ролей в ~75% и назвал
пять пробелов. Задача — закрыть их. Модель прав при этом остаётся как есть:
роли, разрешения и двухуровневая мультитенантность работают, дыра не в модели,
а в том, что её не везде применяют.

## Переоценка пробелов

Проверка кода изменила и формулировку, и severity трёх пунктов из пяти.

| Пробел из аудита | Что выяснилось | Решение |
| --- | --- | --- |
| Мутации не скоупятся по тенанту | Подтверждено. `authhttp.Scope` вызывается ровно в трёх обработчиках чтения; остальные десять из тринадцати маршрутов под `/api/territories/{slug}` не проверяют ничего | **Делаем**: гейт на границе территории |
| Чтения дочерних ресурсов не скоупятся | Подтверждено, тот же корень | **Тем же гейтом** |
| `/api/assets/{hash}` без авторизации | Не открытая дверь, а capability-ссылка: хеш — SHA-256 содержимого. **Severity в аудите завышена.** Но после гейта территории чужие хеши перестают выдаваться scene-бандлом, и остаётся настоящее свойство: у ссылки нет отзыва | **Делаем**: закрываем `Authenticate` — отзыв даёт сессия |
| SSE без авторизации | То же. Идентификатор задачи — 128 бит из `crypto/rand`, перебор невозможен, «перебор идентификаторов» в аудите — неверная формулировка | **Делаем**: `Authenticate` |
| Токен в localStorage | Подтверждено | **Делаем**: httpOnly-кука |
| *(вне списка аудита)* Модели без тенанта | У `models` нет колонки владельца — это общая библиотека по замыслу, а не утечка. Требование заказчика: не открывать их без аккаунта. JSON-API уже за `Authenticate`; геометрия и превью идут через `/api/assets` | **Закрывается** пунктом про ассеты |

## Ключевое решение: кука вместо подписанных ссылок

Первоначально ассеты предполагалось закрыть подписанными ссылками: документы
рендерятся в `<iframe>`, панорамы и превью — через `<img>`, и заголовок
авторизации туда не поставить.

Проверка раскладки прода отменила эту необходимость. **SPA и шлюз в проде — один
origin**: nginx отдаёт статику и проксирует `/api` на `localhost:8080`,
`VITE_API_URL` пустой. Значит httpOnly-кука поедет с `<img>`, `<iframe>`,
`EventSource` и загрузчиками three.js сама, без единой правки в местах загрузки.

| | Подписанные ссылки | Кука |
| --- | --- | --- |
| Работает с `<img>` / `<iframe>` | да, ради этого и нужны | да, само собой |
| Срок жизни | есть | есть, TTL сессии |
| **Отзыв** | **нет** — ссылка живёт до истечения даже после выхода | **есть** — выход, заморозка и смена ролей уже убивают сессию мгновенно |
| Новый механизм | HMAC, ключ, эндпоинт выдачи, правка `assetUrl` | нет |

Подписанные ссылки дают срок жизни, независимый от сессии. Здесь это не
преимущество, а ровно тот недостаток, который надо было убрать: у выданной
ссылки нет способа протухнуть при увольнении сотрудника. Отбрасываем механизм,
цель закрываем дешевле.

## Решения

| Вопрос | Решение |
| --- | --- |
| Где проверяется доступ к территории | Middleware по префиксу шаблона маршрута, не в обработчиках |
| Код отказа для чужой территории | 404, а не 403 — согласовано с существующим `GetTerritory` |
| Скоуп в трёх обработчиках, где он уже есть | Оставляем — защита в глубину, цена одна индексированная выборка |
| Скоуп у моделей | Не делаем; общая библиотека по замыслу |
| Аутентификация ассетов | `Authenticate`, без привязки к территории |
| Аутентификация SSE | `Authenticate`, без привязки задачи к территории |
| Хранение сессии в браузере | httpOnly-кука `SameSite=Lax` |
| Bearer-заголовок | Остаётся — им живут curl, тесты и внешние клиенты |
| CSRF | `SameSite=Lax`; отдельного токена нет |
| Дев-топология | Одно-origin через дев-прокси Vite, как в проде |
| Подписанные ссылки | Не делаем |

## Архитектура

### 1. Гейт на границе территории

Все тринадцать дочерних маршрутов адресуются слагом территории:

```
/api/territories/{slug}                      /api/territories/{slug}/placements
/api/territories/{slug}/admins               /api/territories/{slug}/placements/{id}
/api/territories/{slug}/source                        …/placements/{id}/visibility
/api/territories/{slug}/scene                /api/territories/{slug}/panoramas
/api/territories/{slug}/artifacts            /api/territories/{slug}/panoramas/{id}
/api/territories/{slug}/artifacts/{lod}      /api/territories/{slug}/documents
                                             /api/territories/{slug}/documents/{id}
```

**Middleware, а не проверка в каждом обработчике.** Дыра возникла именно потому,
что скоуп нужно было не забыть протащить — и его забыли в десяти местах из
тринадцати. Проверка в обработчике воспроизводит ту же хрупкость: следующий
дочерний ресурс снова её не получит. Механизм переиспользует приём, который уже
работает у `RequirePermissionForRoute` — чтение шаблона маршрута из chi:

```go
// httpapi/territory_gate.go
func (s *Server) RequireTerritoryAccess(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        pattern := chi.RouteContext(r.Context()).RoutePattern()
        if !strings.HasPrefix(pattern, "/api/territories/{slug}") {
            next.ServeHTTP(w, r); return
        }
        scopeAdminID, allAccess := authhttp.Scope(r.Context())
        if allAccess {                       // Root
            next.ServeHTTP(w, r); return
        }
        if scopeAdminID == "" {              // принципал без компании — fail closed
            notFound(w); return
        }
        if _, err := s.svc.GetTerritory(r.Context(), chi.URLParam(r, "slug"), scopeAdminID); err != nil {
            notFound(w); return
        }
        next.ServeHTTP(w, r)
    })
}
```

`notFound(w)` пишет тот же конверт `{"code":"not_found","message":…}`, что
отдают обработчики через `apperr.Write` — ответ чужому тенанту обязан быть
неотличим от ответа на несуществующий слаг, включая тело.

Монтируется в `/api`-подроутере **после** `RequirePermissionForRoute`: проверка
разрешения не ходит в сеть, и вызывающему, которому и так полагается 403, не
нужно оплачивать gRPC-запрос.

**Проверить, что `RoutePattern()` и `URLParam` вообще заполнены в этой точке.**
chi собирает цепочку как `chain(middlewares, routeHTTP)` — то есть `Use`-мидлвари
исполняются до сопоставления маршрута, и в обычном `Mux` шаблон был бы пуст.
Здесь это работает, потому что мидлварь висит на встроенном подроутере из
`r.Group(...)`, куда родитель передаёт управление уже после сопоставления; тем
же приёмом живёт `RequirePermissionForRoute`, и живая проверка на этой ветке
подтвердила, что он срабатывает. Но подтверждение косвенное, а цена ошибки —
молчаливый пропуск, поэтому это должно быть покрыто сквозным тестом, а не
рассуждением.

- `POST /api/territories` не подпадает: у шаблона нет `{slug}`.
- `ListTerritories` остаётся фильтром, а не гейтом: это список, слага нет.
- 404, а не 403: 403 подтверждает существование территории, а для чужого тенанта
  её не должно существовать. Так же ведёт себя `GetTerritory` сегодня.
- **Скоуп в `GetTerritory` и `GetSceneBundle` не убираем.** Он станет
  дублирующим, но убрать его — значит поставить корректность обработчика в
  зависимость от того, что middleware смонтирован. Ровно этот вид связи уже
  подвёл здесь однажды: `/api/audit.csv` живёт вне `/api`-группы и свои гейты
  получает вручную.
- `ponytail:` потолок — один дополнительный индексированный запрос на каждый
  дочерний вызов, включая scene-бандл, где он дублирует внутренний скоуп. Если
  проявится на профиле, кэшировать в пределах запроса.

### 2. Дев становится одно-origin

Прод уже такой. Дев — нет, и именно из-за этого куке пришлось бы обрастать
`withCredentials` в `EventSource`, `credentials: 'include'` в `fetch`, настройкой
PDF.js и сужением CORS.

Вместо этого дев приводится к топологии прода:

- `vite.config.ts`: прокси `/api` включён **по умолчанию** на
  `http://localhost:8080`, а не только при заданном `VITE_DEV_PROXY`. Переменная
  остаётся как переопределение цели.
- `.env.development`: `VITE_API_URL` пустой, как в `.env.production`.
- Порт дев-сервера по умолчанию — `3000`, а не `5173`: `PASSKEY_RP_ORIGINS`
  прибит к нему, и запуск на 5173 ломает WebAuthn непрозрачным `SecurityError`
  без единой записи в логе, о чём предупреждает README.

Кросс-доменных запросов не остаётся вовсе, поэтому CORS с `AllowCredentials`
не нужен и `GATEWAY_ALLOWED_ORIGINS` не трогаем.

Этот репозиторий уже обжигался на расхождении дева и прода — пустой
`VITE_API_URL` поймали тем, что прод молча собирался с `undefined/api/...`.
Одинаковая топология убирает почву под таким классом находок.

### 3. Сессия в httpOnly-куке

**Кука** `andrey_session`: `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` по
конфигу, `Max-Age` = `GATEWAY_SESSION_COOKIE_TTL` (по умолчанию `720h`, под
абсолютный TTL сессии в auth).

`Secure` по умолчанию **true**: неверно настроенный прод хуже сломанного дева.
Локальный compose выставляет `false` явно, потому что дев работает по http.

Кука переживает `Max-Age`, превышающий серверный TTL сессии, без вреда: сессия
протухнет раньше, `ValidateToken` вернёт 401, клиент уйдёт на логин.

**Где ставится:** на входе (`/api/auth/login`), на подтверждении второго фактора
(`/api/auth/login/2fa`) и на завершении passkey-церемонии
(`/api/auth/passkey/login/finish`). Снимается на выходе (`Max-Age=-1`) вместе с
вызовом logout в auth.

**Как читается:** `Authenticate` принимает **куку или заголовок**
`Authorization`, в таком порядке. Bearer остаётся: им живут curl, тесты и внешние
клиенты, а от XSS защищает не отсутствие Bearer, а то, что токен не лежит у
браузера на диске.

**`withToken` кладёт в контекст тот токен, которым запрос аутентифицировался** —
куку или Bearer, что нашлось. Иначе разрешение подписей в журнале аудита,
которое форвардит этот токен в auth, перестанет работать для браузерных
запросов.

**Токен продолжает возвращаться в теле ответа на вход.** Иначе неоткуда взяться
Bearer у не-браузерных клиентов. Сознательный компромисс: XSS сможет прочитать
токен в момент входа, но не достать лежащий — а именно лежащий токен и есть то,
что крадут.

**CSRF закрывается `SameSite=Lax`**, а не отдельным токеном: кросс-сайтовый
POST куку не понесёт, а состояние в этом API меняют только POST/PUT/PATCH/DELETE
— GET-мутаций нет.

**Фронт:**

- `client.ts` перестаёт слать `Authorization`; кука едет сама на относительных
  путях.
- `token-store.ts` заменяется на `session-marker.ts`: булев маркер «сессия была»
  без секрета. Семантика гварда сохраняется сегодняшняя — он и сейчас не
  проверяет валидность, а первый `meQuery` ловит 401 и уводит на логин.
- Экспорт журнала в CSV перестаёт вручную ставить `Authorization`; на
  одно-origin запросе кука едет сама.

### 4. Ассеты и SSE за `Authenticate`

Оба маршрута живут на корневом роутере не случайно: ассеты обходят ETag и
сжатие (бинарь со своим ETag), SSE нельзя буферизовать. Поэтому не переносим их
в `/api`-группу, а вешаем `Authenticate` поштучно — как уже сделано для
`/api/audit.csv` и `/api/metrics/query`:

```go
r.With(authH.Authenticate).Get("/api/assets/{hash}", assetProxy.ServeHTTP)
r.With(authH.Authenticate).Head("/api/assets/{hash}", assetProxy.ServeHTTP)
r.With(authH.Authenticate).Get("/api/jobs/{id}/events", apiServer.WatchJobEvents)
```

**Ассеты не скоупятся по территории, и это не недоделка.** Хеш адресует
содержимое и дедуплицируется между территориями и моделями — у блоба нет одной
территории, к которой его можно привязать. Потолок записываем прямо: любой
аутентифицированный, знающий хеш, его получит. После гейта территории чужие
хеши перестают выдаваться, так что это соразмерно.

**SSE — только аутентификация, без привязки задачи к территории.**
Идентификатор — 128 бит из `crypto/rand`, выдаётся только создателю. Проверка
территории поверх неугадываемого идентификатора защищала бы от того, чего нет.

## Порядок работ

Порядок здесь — часть дизайна. Закрыть ассеты раньше куки значит сломать
просмотр сцен на всё время между двумя коммитами.

1. **Гейт территории.** Не трогает фронт, разворачивается отдельно.
2. **Дев на одно-origin.** Подготовка, ничего не ломает.
3. **Кука.** Бэкенд ставит и принимает, фронт переходит на маркер.
4. **Ассеты и SSE.** Только теперь, когда куке есть на чём приехать.

## Тесты

**Гейт территории:**

- Таблица по всем тринадцати шаблонам, вытащенным из `openapi.yaml`: префикс
  middleware обязан накрывать каждый. Так маршрут, случайно выпавший из-под
  гейта, валит сборку, а не тихо открывается.
- Чужой тенант получает 404 на плейсментах, панорамах, документах, артефактах и
  самой территории; свой — 200.
- Root проходит везде.
- Принципал без компании получает 404, а не пропускается.
- `POST /api/territories` гейт не задевает.
- **Сквозной тест через настоящий роутер**, а не только по карте: запрос уходит
  в собранный `InitRouter`, и чужой тенант получает 404. Существующий
  `route_permissions_test.go` проверяет только содержимое карты — он прошёл бы и
  в мире, где `RoutePattern()` внутри мидлвари пуст и гейт не срабатывает
  никогда. Тот же тест заодно покрывает и `RequirePermissionForRoute`, у
  которого этой проверки сегодня нет.

**Кука:**

- Вход ставит куку с `HttpOnly`, `SameSite=Lax`, `Path=/` и `Max-Age` из конфига.
- `Secure` следует конфигу в обе стороны.
- `Authenticate` принимает куку; принимает Bearer; при обоих предпочитает куку.
- Выход снимает куку.
- Токен из куки попадает в контекст (иначе ломаются подписи в журнале).

**Ассеты и SSE:** без сессии — 401; с сессией — 200.

**Фронт:** гвард уводит на логин без маркера; клиент ходит на относительные пути
и не ставит `Authorization`.

## Чего не делаем

- **Подписанные ссылки на ассеты** — кука закрывает ту же цель и добавляет
  отзыв, которого у подписи нет. Понадобятся, если ассеты придётся отдавать
  наружу, где куки нет: в отчёт, письмо или стороннюю систему.
- **Тенантность моделей** — общая библиотека по замыслу заказчика; требование
  «не открыть без аккаунта» закрывается аутентификацией ассетов.
- **Привязка ассета к территории** — блоб дедуплицируется между территориями, у
  него нет одной территории.
- **Привязка SSE-задачи к территории** — идентификатор неугадываем.
- **Отдельный CSRF-токен** — `SameSite=Lax` покрывает, GET-мутаций в API нет.
- **Удаление скоупа из трёх обработчиков, где он уже есть** — дублирование
  дешевле, чем зависимость корректности от факта монтирования middleware.
