# Десктоп-обёртка приложения (Electron, тонкий клиент)

**Дата:** 2026-07-27
**Статус:** утверждён к планированию

## Цель

Собрать приложение в устанавливаемый бинарник под Windows / macOS / Linux.
Бинарник — тонкий клиент: он запускает встроенный Next.js-сервер и подключается
к уже работающему прод-бэкенду. Бэкенд (Go-сервисы, postgres, redis) НЕ входит
в бинарник и не изменяется.

## Ключевое наблюдение об архитектуре фронтенда

Фронтенд — Next.js 16 с серверными компонентами и BFF-прокси, а не статический SPA.
Доступ к бэкенду устроен так:

- **Браузер (клиент)** ходит только **same-origin**:
  - `assetUrl()` возвращает относительный `/api/assets/...`;
  - `http/client.ts` на клиенте использует пустой base (same-origin);
  - SSE в `use-job-stream.ts` использует `NEXT_PUBLIC_API_URL ?? ""` → same-origin.
- **Next-сервер (BFF)** проксирует `/api/*` в реальный gateway через серверную
  переменную `GATEWAY_URL`, подставляя Bearer из httpOnly-куки `session`.

Следствие: если оставить `NEXT_PUBLIC_API_URL` пустым, браузер общается ТОЛЬКО
со своим localhost-сервером. CORS не нужен, куки остаются same-origin.
`output: "standalone"` уже включён в `next.config.ts`, поэтому `next build`
производит самодостаточный `.next/standalone/server.js`.

## Архитектура

```
Electron main process
 ├─ child_process.fork('.next/standalone/server.js',
 │      { env: { ...process.env,
 │               ELECTRON_RUN_AS_NODE: '1',   // запуск Next во встроенном в Electron Node
 │               GATEWAY_URL: 'http://85.192.26.113:8080',
 │               PORT: '34115',               // фиксированный порт
 │               HOSTNAME: '127.0.0.1' } })
 │    └─ Next BFF проксирует /api/* → прод-gateway, инжектит Bearer из куки
 └─ BrowserWindow.loadURL('http://127.0.0.1:34115')
        └─ браузер ходит ТОЛЬКО в свой localhost (same-origin) — CORS отсутствует
```

Отдельный Node-рантайм не бандлим — используем встроенный в Electron через
`ELECTRON_RUN_AS_NODE=1`.

## Компоненты

Всё новое живёт в новой папке `desktop/` в корне репозитория. Бэкенд и `frontend/`
не изменяются (единственное возможное исключение — env на проде для passkey, см. ниже).

- **`desktop/package.json`** — зависимости `electron` и `electron-builder`, скрипты
  `start` (dev-запуск) и `dist` (сборка бинарников).
- **`desktop/main.js`** (~70 строк) — точка входа Electron:
  1. форкнуть Next-сервер с env выше на фиксированном порту 34115;
  2. дождаться готовности порта (poll GET `http://127.0.0.1:34115/` до ответа);
  3. создать `BrowserWindow` и `loadURL`;
  4. убить дочерний процесс на `window-all-closed` / `before-quit`.
- **`desktop/build.mjs`** — сборочный скрипт:
  1. `next build` в `frontend/`;
  2. скопировать `frontend/.next/static` → `.next/standalone/.next/static`
     и `frontend/public` → `.next/standalone/public`
     (standalone-output их не копирует — известный нюанс Next);
  3. запустить `electron-builder`.
- **electron-builder конфиг** (в `desktop/package.json` или `electron-builder.yml`):
  таргеты `nsis` (Windows), `dmg` (macOS), `AppImage` (Linux); в `files`/`extraResources`
  включить standalone-дерево.

## Зашитая конфигурация

- `GATEWAY_URL = http://85.192.26.113:8080` (серверная переменная Next BFF).
- `NEXT_PUBLIC_API_URL` — **не задаётся** (пустая), чтобы браузер оставался same-origin.
- Порт Next-сервера — **фиксированный 34115**.

## Известные потолки (осознанные упрощения, апгрейд по необходимости)

1. **Буферизация SSE-прогресса конвертации.** Идёт через Node-прокси Next
   (см. комментарий в `use-job-stream.ts`), поэтому полоска прогресса может «застыть»
   до завершения конвертации. Уже есть fallback — 4-сек `router.refresh` поллинг.
   Апгрейд (браузер напрямую в gateway + CORS на бэке) — только если реально мешает.
2. **Passkey/WebAuthn привязан к origin.** RP на бэке должен разрешать
   `http://localhost:34115`. Логин по паролю + 2FA (куки) работает без нюансов.
   Для passkey в десктопе: добавить `http://localhost:34115` в `PASSKEY_RP_ORIGINS`
   на проде, либо в десктоп-сборке не полагаться на passkey. Не блокер.
3. **Подпись/нотаризация macOS.** Для внутреннего использования можно без подписи
   (первый запуск — правый клик → «Открыть»). Подпись добавляется позже при раздаче.

## Проверка

`desktop/main.js` содержит нетривиальную логику (ожидание готовности порта, kill
дочернего процесса). Оставляем один запускаемый self-check: скрипт стартует
Next-сервер, поллит `http://127.0.0.1:34115/` до 200, затем убивает процесс и
выходит с кодом 0/1. Без фреймворков.

## Вне объёма (YAGNI)

- Автообновление (electron-updater).
- Настраиваемый в UI адрес сервера — адрес зашит.
- Бандлинг бэкенда/БД в бинарник (это был бы offline-вариант, отклонён).
- Глубокая интеграция с ОС (трей, нативное меню сверх дефолтного, deep links).
