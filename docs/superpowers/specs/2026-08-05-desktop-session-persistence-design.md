# Сессия десктоп-клиента переживает перезапуск — дизайн

**Goal:** пользователь, вошедший в десктоп-приложение, остаётся в аккаунте
после его перезапуска. Сейчас логин требуется при каждом старте.

**Область:** `desktop/src-tauri/` — `server.rs`, `main.rs`, `state.rs`,
`Cargo.toml`. Фронтенд и бэкенд не меняются.

**Что в объём не входит:** барьер ожидания чтения keychain, `dataDirectory`
вебвью, любые правки маршрутного guard-а во фронтенде, автообновление.

---

## Диагноз

Токен в связке ключей не терялся. Он там лежит и после перезапуска:

```
svce="fun.vbncursed.andrey.desktop"  acct="session"
```

Стирает его сам повторный логин: `POST /api/auth/login` → `clears_session`
(`proxy.rs:264`) → `session::clear()`. А логин случается потому, что SPA до
API вообще не доходит.

### Корневая причина: эфемерный порт loopback-сервера

`server.rs:26` биндит `("127.0.0.1", 0)` — порт новый на каждый запуск. Лог
приложения подтверждает: `61605`, `61738`, `61807`, `61827`.

Origin вебвью — `http://127.0.0.1:<порт>`, а `localStorage` партиционирован по
origin. Маркер сессии `andrey.authed`
(`frontend/src/auth/infrastructure/session-marker.ts:10`) остаётся в бакете
прошлого порта. Хранилище WebKit показывает это прямо:

```
tGHLQRWF-…/  -> andrey.authed     ← прошлый порт
kjg8RNx6…/   -> (пусто)           ← текущий порт
W031Rewa…/   -> (даже не создан)
```

`requireAuth` (`frontend/src/routes/guard.ts:18`) — синхронный, без сетевого
запроса: нет маркера → `redirect to /login`. Прокси с живой кукой в jar-е никто
не спрашивает.

Цепочка целиком: новый порт → пустой `localStorage` → `isAuthed()=false` →
`/login` → пользователь логинится → `clears_session()` удаляет прежнюю запись
keychain → пишется новая. «Токен затирается» — следствие, а не причина.

Эфемерный порт роняет и остальное, что живёт на origin: HTTP-кэш WebKit,
IndexedDB и service worker (`/sw.js` переустанавливается каждый старт и тянет
бандл заново).

### Вторая, латентная проблема

Восстановление сессии из keychain намеренно вынесено в `spawn_blocking`
(`main.rs:73`) — синхронное чтение на macOS открывает диалог авторизации всякий
раз, когда подпись бинаря изменилась с момента записи (то есть после любой
пересборки и любого обновления приложения), и блокировать на нём старт значит
не показать ни окна, ни сервера.

Из-за этого первый запрос приложения гонится с восстановлением. Сегодня гонка
не стреляет: SPA останавливается на `/login` и до API не доходит. После фикса
origin первым же запросом пойдёт `/api/auth/me`. Если он выиграет гонку,
гейтвей ответит 401, `clears_session(401)` вызовет `state.clear_session()`, и
запись keychain будет удалена **навсегда** — разовый сбой станет постоянным
разлогином.

Поэтому обе правки идут одним заходом: первая без второй меняет
детерминированный баг на плавающий.

---

## Решение

### 1. Фиксированный порт loopback-сервера

`server::spawn` перестаёт брать порт у ядра:

```rust
/// Ниже эфемерного диапазона всех трёх платформ (Linux 32768–60999,
/// macOS/Windows 49152–65535), иначе ядро само раздаст его чужому процессу.
const PORT: u16 = 17817;
```

Порядок разрешения: `DESKTOP_PORT` из окружения → `PORT` → `0`.
Env-override существует, чтобы дев-сборка запускалась рядом с установленной
копией и не отбирала у неё origin.

Origin вебвью становится постоянным, `localStorage` — тем же самым, маркер
переживает перезапуск, guard не срабатывает, прокси отдаёт восстановленную
сессию. Попутно переживают перезапуск HTTP-кэш, IndexedDB и service worker.

### 2. Одна копия приложения на машину

`tauri_plugin_single_instance` первым в билдере (`main.rs`), в колбэке —
`get_webview_window("main").set_focus()`.

На macOS второй запуск .app и так активирует существующее окно; на Windows
(цель в матрице CI) стартует настоящий второй процесс, забирает fallback-порт,
и его логин удаляет запись keychain у первого. Плагин закрывает это
структурно.

### 3. 401 больше не стирает связку ключей

`state.rs`:

```rust
pub fn clear_session(&self) {
    let mut s = self.session.lock().unwrap();
    // Пусто — значит восстановление из keychain ещё не отработало, и этот
    // процесс не доказал, что сохранённый токен протух. Стирать нечего.
    if s.take().is_some() {
        crate::session::clear();
    }
}
```

Разбор случаев:

| случай | сессия в памяти | keychain |
| --- | --- | --- |
| логаут | `Some` | чистится, как раньше |
| 401 при живой сессии | `Some` | чистится, как раньше |
| 401 в окне старта | `None` | цел — следующий запуск восстановится |
| логин при живой сессии | `Some` | чистится; инвариант «не отдать B блобы A» сохранён |
| логин, сессии никогда не было | `None` | удалять нечего |

Остаточный риск, осознанный: восстановление, приземлившееся после 401, положит
в jar уже отвергнутый токен. Безвредно — SPA в этот момент на `/login`, а логин
перезапишет и jar, и keychain.

## Что проверено и менять не нужно

**Устаревшая кука нонса.** Постоянный origin означает, что вебвью может
прислать `dsk` от прошлого запуска. Поток разбирается сам: `dispatch("/")` не
находит совпадения, но `Route::Index` отдаётся без нонса намеренно, а
`serve_static` видит `?dsk=<новый>` в query и ставит `Set-Cookie` с тем же
именем и `Path=/` — прежнее значение перезаписывается до того, как уйдёт первый
подресурс. Фиксируется тестом, кода не требует.

**Безопасность.** Порт становится предсказуемым, но предсказуемость никогда не
была защитой: 65 тысяч loopback-портов сканируются за миллисекунды. Порт
охраняет per-run нонс (`guard.rs`), и он не меняется.

**Дисковый кэш.** `blobs/` и `snapshots/` ключуются по `(хост апстрима,
user_id)` (`state::resolve_cache_root`) и от порта не зависят.

## Деградация

| исход `bind` | поведение | что видит пользователь |
| --- | --- | --- |
| `17817` свободен | обычный путь | остаётся в аккаунте между запусками |
| занят чужим процессом | fallback на `0` + `log::warn!` | логинится один раз — сегодняшнее поведение |
| и `0` не забиндился | нативный диалог + `exit(1)` (уже есть) | сообщение об ошибке вместо пустого окна |

Fallback не оставляет полусостояний: маркер потерян, guard уводит на `/login`,
сессия в прокси при этом жива, логин перезапишет и её, и keychain.

## Тестирование

По конвенции репозитория решение, которому нужен тест, живёт в чистой функции:

- `preferred_port(env: Option<&str>) -> u16` — `None` → 17817, `Some("1234")` →
  1234, мусор → 17817.
- `bind_loopback(preferred) -> io::Result<TcpListener>` — тест занимает
  эфемерный порт, узнаёт его номер, просит именно его и получает слушателя на
  другом порту. Хардкод 17817 в тест не попадает, поэтому в CI ничего не
  отбирается.
- `clears_keychain(current: Option<&Stored>) -> bool` — решение из пункта 3
  отдельно от `session::clear()`, которую в тесте дёргать нельзя: она пишет в
  реальную связку ключей.
- `dispatch("/", nonce, Some("dsk=<старый>"))` → `Static(Index)` — устаревшая
  кука не запирает окно. Роутер-тест здесь невозможен: `serve_static` требует
  `AppHandle`, которого в тестах нет.
- `make -C desktop check` — fmt, clippy, тесты.

Живая проверка на собранном приложении: логин → полный выход → запуск → сразу
внутри; в `~/Library/WebKit/fun.vbncursed.andrey.desktop/WebsiteData/Default`
новых бакетов не прибавилось; в логе нет `warn` про занятый порт.

## Отвергнутые варианты

**Отвязать SPA от `localStorage`** — расширить `INIT_SCRIPT` до
`window.__DESKTOP_AUTHED__` или отдать эндпоинт `/__desktop/session`. На момент
`setup()` сессия ещё не прочитана, значит либо блокируем старт (запрещено —
см. диагноз), либо делаем guard асинхронным. И главное: origin по-прежнему
плавает, кэш, IndexedDB и service worker продолжают сбрасываться. Лечит один
симптом из четырёх.

**Убрать маркер, сделать `requireAuth` асинхронным.** Архитектурно честнее
всего: сессия — httpOnly-кука, странице про неё знать нечего. Но маркер введён
ровно чтобы не платить round-trip на каждом переходе, и это регресс UX в вебе
ради десктопа. Origin опять же не чинится.

**`dataDirectory` вебвью** (`tauri.conf.json`) — на macOS и iOS не
поддерживается, и партиционирование по origin оно всё равно не отменяет.

**Барьер ожидания keychain** — `watch`-канал плюс `timeout`, чтобы `/api`-
запросы ждали восстановления. Убирает гонку целиком, но добавляет состояние и
таймаут ради окна в единицы миллисекунд. Апгрейд-путь, если гонка окажется
штатной.
