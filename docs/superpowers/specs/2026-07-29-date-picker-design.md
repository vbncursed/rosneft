# Календарь для выбора даты — дизайн

Дата: 2026-07-29
Статус: утверждён, готов к планированию реализации

## Задача

В фильтрах журнала аудита поля `From` / `To` — нативные `<input type="date">`
(`audit/presentation/components/audit-filters.tsx:70-85`). Браузерный пикер
выглядит чужеродно на тёмной «стеклянной» вёрстке остального интерфейса и
по-разному в каждом браузере. Нужен собственный компонент календаря.

## Что уже есть в коде (писать заново не нужно)

Поповер-инфраструктура целиком существует в `shared/presentation/components/dropdown/`:

| Что нужно календарю | Что переиспользуем |
| --- | --- |
| Позиционирование по триггеру | `dropdown/use-anchored-position.ts` — `useAnchoredPosition(ref, open)`, пересчёт на scroll (capture) и resize |
| Выход из stacking context | `createPortal(…, document.body)` — паттерн из `dropdown-menu.tsx:56`; `backdrop-blur` соседних панелей иначе перекрывает поповер |
| Анимация | `motion/presets`: `scaleFade` + `quick` + `useResolvedVariants` (обязателен `prefers-reduced-motion`) |
| Закрытие | outside-`mousedown` + `Esc` из `dropdown.tsx:87-104`, с возвратом фокуса на триггер |
| Клавиатура без roving tabindex | Паттерн `dropdown.tsx`: фокус остаётся на кнопке-триггере, подсветка через `aria-activedescendant` |
| Стиль | Классы триггера `dropdown.tsx:148`, панели `dropdown-menu.tsx:68` |

**Новую зависимость не добавляем.** Ни одна дейтпикер-библиотека не нужна:
арифметика календаря — это ~45 строк чистых функций.

## Контракт данных — не меняется

Значение компонента — строка `YYYY-MM-DD`, `""` = «не задано». Это ровно то,
что отдавал нативный инпут, поэтому:

- `AuditFilters` (`audit/domain/audit-entry.ts:21-27`) — без изменений;
- `toBound()` (`audit/infrastructure/audit-gateway.ts:45-48`), расширяющий дату
  до `T00:00:00Z` / `T23:59:59Z` — без изменений;
- `ExportButton`, `use-audit-log.ts`, backend — не затронуты.

Меняется только визуальный слой двух полей.

## Решения

| Вопрос | Решение |
| --- | --- |
| Форма | Два одиночных поповера (`From`, `To`), не единый range-пикер |
| Локация | `shared/` — общий примитив, потребителей уже двое |
| Гранулярность | Сутки. Время дня не вводим |
| Границы | Будущее заблокировано; `From` не может быть позже `To` и наоборот |
| Ввод текстом | Нет. Триггер — кнопка; клавиатура работает стрелками внутри календаря |
| Первый день недели | Понедельник, хардкод (`ponytail:`-комментарий) |
| Локаль подписей | Локаль браузера через `Intl`, как `toLocaleString()` в `audit-row.tsx:8` |
| Сброс фильтра | Кнопка `Clear` в футере панели |

## Архитектура

### 1. `shared/domain/calendar.ts` — чистая арифметика

Прецедент для чистого модуля в `shared/domain/` — `vec3.ts`. Тестируется
`node --test` (`*.test.ts`).

```ts
todayISO(): string                              // "2026-07-29"
addDays(iso: string, n: number): string
shiftMonth(ym: string, delta: number): string   // "2026-07" → "2026-08"
monthOf(iso: string): string                    // "2026-07-29" → "2026-07"
monthGrid(ym: string): string[]                 // ровно 42 ISO-даты
inRange(iso: string, min?: string, max?: string): boolean
toDate(iso: string): Date                       // единственный вход в Date, для Intl
```

Три решения внутри, каждое закрывает конкретную ловушку дат:

1. **Собственная сериализация вместо `toISOString()`.** `toISOString()` отдаёт
   дату в UTC: для пользователя в GMT+5 в 02:00 он вернёт **предыдущий** день.
   Пишем `${y}-${pad(m)}-${pad(d)}` из локальных геттеров.
2. **Собственный парсинг вместо `new Date(iso)`.** `new Date("2026-07-29")`
   по спецификации парсится как UTC-полночь — тот же сдвиг в обратную сторону.
   Разбираем строку и конструируем `new Date(y, m - 1, d, 12)`. **Полдень, а не
   полночь** — так любой DST-переход (±1 час) не может перебросить дату на
   соседние сутки.
3. **Сравнение строк вместо арифметики дат.** У `YYYY-MM-DD` лексикографический
   порядок совпадает с хронологическим, поэтому вся проверка границ — это
   `(!min || iso >= min) && (!max || iso <= max)`. Ни `Date`, ни таймзон.

`monthGrid` всегда отдаёт 42 ячейки (6 недель), начиная с понедельника на или
до 1-го числа. Фиксированная длина = фиксированная высота панели: при
перелистывании месяцев вёрстка не прыгает. Смещение первого дня:
`(first.getDay() + 6) % 7` — переводит нумерацию JS (вс = 0) в «пн = 0».

**Форматирования здесь нет.** `Intl` зависит от локали окружения, а домен
должен быть детерминированным для `node --test`. Названия месяцев и дней
недели формируются в презентации — через `toDate()`, единственную точку, где
ISO-строка становится `Date`.

### 2. `shared/presentation/components/date-picker/date-picker.tsx`

Структурная копия `dropdown.tsx`. Пропсы:

```ts
{
  value: string;                     // "" = не задано
  onChange: (iso: string) => void;   // "" при Clear
  min?: string;                      // включительно
  max?: string;                      // включительно
  ariaLabel?: string;
  placeholder?: string;              // по умолчанию "any"
  className?: string;
}
```

Пропса `label` нет: в фильтрах аудита подпись уже рисует обёртка `Field`
(`audit-filters.tsx:19-26`), второй источник подписи создал бы расхождение.

Состояние: `open`, `month` (видимый месяц), `cursor` (день под клавиатурной
подсветкой). `month` и `cursor` **переинициализируются при каждом открытии** от
`value ?? todayISO()`, зажатого в `[min, max]` — открытие всегда начинается с
текущего выбора пользователя, как `openMenu()` у дропдауна.

Клавиатура на кнопке-триггере:

| Состояние | Клавиша | Действие |
| --- | --- | --- |
| закрыт | `Enter` `Space` `↑` `↓` | открыть |
| открыт | `←` `→` | курсор ±1 день |
| открыт | `↑` `↓` | курсор ±7 дней |
| открыт | `PgUp` `PgDn` | ±1 месяц, курсор на 1-е число нового месяца |
| открыт | `Home` `End` | первое / последнее число видимого месяца |
| открыт | `Enter` `Space` | выбрать курсор (если день доступен) |
| открыт | `Esc` `Tab` | закрыть, фокус назад на триггер |

Курсор, ушедший за пределы видимого месяца, подтягивает `month` за собой. Ход
за `min`/`max` **не выполняется** — курсор просто остаётся на месте
(предсказуемее, чем зажатие к границе).

Триггер: текст = дата в локали браузера либо `placeholder`.
`aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`.

Если файл выйдет за ~150 строк — клавиатура выносится в
`use-calendar-keyboard.ts`, как `use-dropdown-keyboard.ts` у дропдауна.
Заранее не дробим.

### 3. `shared/presentation/components/date-picker/calendar-panel.tsx`

Портал в `<body>`, `motion.div` со `scaleFade`/`quick`. Содержимое:

- шапка: `‹`, подпись месяца (`Intl.DateTimeFormat(undefined, {month:"long", year:"numeric"})`), `›`;
- строка дней недели: короткие названия, полученные форматированием **первых
  семи ячеек самой сетки** (`{weekday:"short"}`). Так заголовок не может
  разъехаться с сеткой — константы «неделя начинается с понедельника» в этом
  файле нет вовсе;
- 42 ячейки-кнопки: дни вне видимого месяца приглушены, недоступные —
  `aria-disabled`, выбранный — cyan-акцентом, курсор — фоном `white/10`
  (те же роли цветов, что у `dropdown-menu.tsx`);
- футер: `Clear` → `onChange("")`.

Доступность. `role="grid"` **не используем**: валидный grid требует
промежуточных `role="row"`, которые ломают `grid-cols-7` (или требуют
`display:contents` и нарезки массива по неделям). Вместо этого каждая ячейка —
обычная кнопка с полным `aria-label` («29 июля 2026 г.»), `aria-pressed` для
выбранного дня, `aria-current="date"` для курсора; подписи дней недели
помечены `aria-hidden`, поскольку каждая ячейка и так называет себя полностью.

Так как фокус остаётся на триггере, перемещение курсора стрелками само по себе
ничего не озвучивает. Поэтому панель содержит `aria-live="polite"` регион с
классом `sr-only`, в который пишется полная дата курсора: скринридер
проговаривает каждый ход. Без него замена нативного инпута была бы регрессией
доступности, а не улучшением.

Каждая ячейка несёт `data-iso` с ISO-датой — по нему её находит тест, не
завязываясь на локаль подписи. Прямой аналог `data-index` в
`dropdown-menu.tsx:90`.

Все интерактивные элементы панели гасят `mousedown` через `preventDefault()`
и несут `tabIndex={-1}` — иначе триггер потеряет фокус до срабатывания коммита
(`dropdown-menu.tsx:92-96`).

Горизонтальный клэмп позиции: в отличие от дропдауна, панель не наследует
ширину триггера, а имеет собственную (~17rem). На узком экране
`rect.left + width` может уехать за правый край, поэтому
`left = min(rect.left, innerWidth - width - 8)`. Вертикальный флип (открытие
вверх при нехватке места снизу) **не делаем**: фильтры аудита живут в верхней
части страницы.

### 4. `audit/presentation/components/audit-filters.tsx`

Замена двух инпутов на `<DatePicker>`. Взаимная блокировка выражается через
уже существующее состояние фильтров, отдельная валидация не нужна:

```
From: min = —              max = value.to || todayISO()
To:   min = value.from     max = todayISO()
```

Комментарий «no picker library for two fields» (строка 69) заменяется на
пояснение, почему собственный компонент, а не нативный инпут.

## Проверки

**`shared/domain/calendar.test.ts`** (`node --test`) — сетка месяца,
начинающегося в воскресенье, и месяца, начинающегося в понедельник (крайние
случаи смещения); февраль 2028 (високосный); длина всегда 42; `addDays` через
границу месяца и через границу года; `shiftMonth` дек→янв и янв→дек;
`monthOf`. Тест на порядок сравнения строк — то, на чём держится вся
логика границ.

**`date-picker.spec.tsx`** (vitest, jsdom) — клик по триггеру открывает
панель; клик по дню вызывает `onChange` с ISO-строкой; день за `max`
не вызывает `onChange`; `Clear` вызывает `onChange("")`; `Esc` закрывает;
стрелка переносит `aria-current` на соседний день. `motion/react` в этом тесте
мокается: exit-анимация оставила бы закрытую панель в DOM и сделала бы любую
проверку закрытия гонкой. Мок сторонней рендер-обёртки — уже принятый в проекте
приём (`panorama-loading-overlay.spec.tsx` так мокает drei).

Позиционирование не тестируем: в jsdom `getBoundingClientRect()` возвращает
нули, тест проверял бы только сам себя.

Соглашения обоих раннеров (нарушать нельзя, иначе тест просто не запустится):
`*.test.ts` для `node --test` импортирует **относительным путём с явным
`.ts`** — алиас `@/` Node не разрешает; `*.spec.tsx` для vitest импортирует
`describe`/`it`/`expect` явно (`globals` выключены) и вешает `afterEach(cleanup)`
руками.

## Скипнуто

| Что | Когда добавлять |
| --- | --- |
| Range-выбор одним поповером | Если два открытия поповера на «выбрать неделю» станут раздражать |
| Пресеты (Today / 7 days / 30 days) | Если в логах видно повторяющиеся одни и те же диапазоны |
| Ввод даты текстом | Если попросят прыгать на дату далеко в прошлом — сейчас это `PgUp` |
| Вертикальный флип панели | Если компонент появится в нижней части экрана |
| Выбор первого дня недели | Если появятся пользователи с воскресной неделей |
| Время дня в фильтре | Если суточной гранулярности перестанет хватать |
